# 強化学習エージェント（agents/TacR）の設計

2026-11-05 着手。参考文献の要点は `RL_DESIGN_DIGEST.md`（教科書 3 冊・論文 6 本を設計の観点で整理したもの）にあります。

## 1. 全体像
- **階層型（オプション／SMDP）**：
  - 上位の判断を学習した方策が行います。各戦闘機が 5 秒ごとに次の 3 つを選びます。
    - 戦術オプション 6 種：護衛機攻撃／戦闘機交戦／自陣護衛／ドラッグ／左右の側方迂回
    - 高度帯 3 種：ルール既定（11 km）／8 km／13.5 km
    - 射撃の積極度 3 種
  - 低レベルの操舵、ミサイル回避、ミサイル支援、射撃管制（LightGBM 命中確率）は、v17 のルールをそのまま使います。
  - 1 試合の判断回数は、1 秒ごとなら 1800 回のところ、約 240 回になります。勝敗という遅れて届く報酬を前の判断に伝えやすくするためです。
- **分散実行・パラメータ共有**：
  - 4 機が**同じネットワーク**を、それぞれ**自分の目線の観測**で実行します。
  - 学習は 4 機分のデータをまとめて行います（MAPPO 型）。報酬はチーム共有です。
- **助言入力**：v17 の司令部が出す提案（オプション・守備機の役割）を観測に含めます。
  - 方策は「v17 に従う」ことから始め、得になる局面でだけ外れることを学習します（残差型の改善）。
  - 提案どおりのオプションを選んだ機体は、v17 の目標割当と守備機の役割もそのまま引き継ぎます。そのため、模倣だけの方策は v17 と**完全に同じ**試合をします（seed 41000 で確認済み）。

## 2. 観測（`agents/TacR/rl2.py`）：自機中心の球座標
- 基準は**自機の水平正面**です。前・右・下を軸にし、重力の向きは固定します。
- 各物体について、次の量を入れます。
  - 方位（sin, cos）・仰角・距離（線形と対数）・高度差
  - 相手の針路（自分の針路との差）・相手のアスペクト（相手の機首から見た自分の方向）・速度・接近速度
- **トークン**（集合として扱い、順序には意味を持たせません）：
  - 自機 1：絶対高度・速度。旋回性能と加速性能は高度・速度別の表で決まるためです（第 3 節）。ほかに、戦域上の位置・残弾・仮想脅威・v17 の提案。
  - 味方 4（データリンク）：僚機 3 と護衛機 1。
  - 敵 9：レーダー・IRST・記憶の融合航跡と、敵護衛機の推定。**最後に見えてからの経過時間**を入れるので、「さっきまで見えていた」が分かります。自機から撃った場合の命中確率（LightGBM）と、正規化した距離 RNorm も入れます。
  - 自軍ミサイル 8。
  - **MWS 4**：方位と**視線角速度**。視線角速度がほぼ 0 なら、衝突コースで接近しています。
- 使う情報は自機の観測・データリンク・センサ航跡だけです（暫定ルール 1）。IRST の並び順には依存しません（暫定ルール 2）。

## 3. シミュレータの物理（ソースで確認済み）
- 機体の加速度には重力成分 g·(速度方向・下向き) が入ります。上昇すると減速し、降下すると加速します。
- 旋回率・横 G・加速度は、高度 13 点 × 速度 15 点の表で与えられます。中間速度で比べると次のとおりです。

  | 高度 | 旋回率 | 最大加速度 |
  |---|---|---|
  | 4.5 km | 0.10 rad/s | 7.3 m/s² |
  | 10.6 km | 0.06 rad/s | 2.8 m/s² |
  | 13.7 km | 0.04 rad/s | 1.7 m/s² |

- 機体の質量は一定です。ミサイルは 153.8 kg から 90.9 kg まで減り、推力は 30 kN です。
- **高度帯を行動に入れた**のは、この性能差と、ミサイルの射程（高い位置から撃つほど伸びる）とのトレードオフを、方策に局面ごとに選ばせるためです。

## 4. ネットワーク（`net2.py` / `net2_np.py`）
- 種類ごとの線形埋め込みのあと、事前正規化型の Transformer 2 層（d=64、4 ヘッド、マスク付き）を通します。
- 自機トークンと全トークンのマスク付き平均を連結し、行動ヘッド 3 つ（オプション・高度帯・射撃の積極度）と価値ヘッドに入れます。パラメータは約 7 万です。
- 敵や味方の数が変わっても、並び順が変わっても、同じように扱えます（DeepSets / Set Transformer の考え方。配布サンプルの SetTransformer.py に相当）。
- 試合中の推論は **numpy** で行い、torch 版との誤差は 1e-7 です。torch がなくても動き、提出物もこの形にします。

## 5. 学習（`rl2/learner.py`、`rl2/driver.py`）
1. **模倣（BC）**：v17 の司令部のラベルで、交差エントロピーを最小化します。価値は、モンテカルロのリターンへの回帰で事前学習します。
2. **PPO（Actor-Critic）**：

   | 項目 | 設定 |
   |---|---|
   | 比率のクリップ | 0.2 |
   | GAE | λ=0.95 |
   | 割引 | γ=0.995／5 秒（約 0.999／秒） |
   | 1 回の更新 | 48 試合、3 エポック、近似 KL が 0.03 を超えたら打ち切り |
   | エントロピー | 0.01 |
   | 最適化 | Adam 3e-4、勾配クリップ 0.5 |

   - 比率は機体ごとに計算し、3 つのヘッドの対数確率の和を使います。
   - 価値は更新前に現在の Critic で計算し直します。
3. **BC 項を残す**：v17 のラベルへの交差エントロピーを、重み 0.5 から始めて 0.05 まで下げ、そこで止めます。ゼロにはしません（InstructGPT の PPO-ptx の考え方）。
4. **報酬**（学習時のみ、試合のイベントログから計算）：
   - 敵戦闘機の撃墜 +0.1、自機の喪失 −0.1。
   - 終端は 2×(競技得点−0.5) − 0.03×外れ弾数。
   - 戦死した機体には、それ以後のチーム報酬の割引和を最後の遷移で与えます。死後の結果も、それまでの行動の責任とするためです。
5. **リーグ**：
   - 相手は、実戦ログに出てきた型のルールエージェント 9 種（v17・v15・高速 10 km・低高度突撃・p2・sn・scr・v7・ベンチマーク）、方策のスナップショット（10 版ごと）、ミラー自己対戦（20%）です。
   - PFSP で、勝てない相手ほど多く当てます。重みは (1−得点)² です。
6. **分散の仕組み**：
   - Snowflake のノートブックを複数ノードに広げ（`scale_cluster`）、Ray のタスクとして各ノードで試合を Python 3.10 の子プロセスで実行します。
   - 学習器は先頭ノードで動き、試合を止めずに更新します（非同期）。結果には方策の版番号を付け、2 版より古いものは捨てます。
   - ステージへの読み書きは、チェックポイントの保存（5 版ごと）だけです。

## 6. 評価
- 同じ seed・同じ色で、学習方策（貪欲）と v17 のルールを並べて比べます（対になる比較）。
- 相手は 8 種で、差の 95% 信頼区間を出します。
- 実戦に出すのは、v17 を有意に上回った版だけです。
