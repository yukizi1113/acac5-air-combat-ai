# 第5回空戦AIチャレンジ 技術資料（草稿）

## 1. 問題分析

### 1.1 評価式の分解
- 勝者得点 = 0.6 + 0.3×(命中弾数/発射弾数) + 0.1×TimePoint、敗者 = 1−勝者得点、引分 0.5。
- 命中率は**陣営の全発射弾**（戦闘機・護衛対象機いずれへの射撃も含む）で計算される。
  - 1発で護衛対象機を撃墜して勝てば 1.0 点。外れ弾1発ごとに命中率が下がるため、
    「撃てば当たる射撃だけを撃つ」ことが直接得点になる。
  - 追加の1発（命中確率 p）が期待命中率を改善するのは p > 現在の命中率 のときに限られる
    （(h+p)/(n+1) > h/n ⇔ p > h/n）。
- TimePoint は 900 s 以内の撃破で満点。ベンチマーク相手では 400〜600 s 決着が可能で、
  主眼は「勝率」と「命中率」。
- 評価は Glicko-2。対戦ごとの得点の期待値を上げると同時に、取りこぼし（敗北・引分）を減らす頑健性が重要。

### 1.2 シナリオから導かれる事実（シミュレータのソース・設定から確認）
| 項目 | 値 | 戦術的含意 |
|---|---|---|
| レーダ探知距離 | 80 km × (0.8–1.2) × RCS^(1/4) | 戦闘機同士は 51–96 km。3次元航跡が得られ、射撃に必須 |
| IRST探知距離 | 120 km × (0.8–1.2) × IR^(1/2) | 戦闘機は 77–144 km。**方位のみ**、航跡IDはセンサごとに匿名 |
| 護衛対象機 | RCS×16 → レーダ約2倍(160 km)、IR×4 → IRST約2倍(240 km) | 開始時点からIRSTで見えることが多い |
| 護衛対象機の軌道 | 自陣から120 km、南北±100 kmの周回、MWS検知時のみ回避 | 位置の事前分布が非常に強い |
| ミサイルシーカ | 10 km / 覆域60° / 視野15° | 終末誘導まで母機（または僚機）のレーダ航跡が必要 |
| MWS | シーカがロックした誘導弾の方向のみ | 警報は着弾数秒前。正対射撃に対してはほぼ手遅れ |
| 射撃承認遅延 | 1–5 s、同時保持1件 | 射撃要求の重複は無意味。目標ごとの割当が必要 |

### 1.3 データで確認した交戦の本質
（ベンチマーク相手の実戦ログ約400発と、交戦ラボ（後述）の結果）
- 敵ミサイル命中率は**飛翔終盤の被射撃機のアスペクト**でほぼ決まる：
  終盤に背を向けている（>135°）と 0 %（239発中0）、正対だと約35 %。
- 警報（MWS）を契機とする回避は正対射撃に対してほぼ無効（ラボで正対射撃の命中率 100 %）。
- 対戦闘機の長距離射撃（25 km超）は、相手が予防的に反転するため命中率 6 % 程度。
- 護衛対象機への射撃は 60 km 以内で 60–100 %、70 km 超では 14 %。

## 2. システム構成（階層型）

```
観測 ──► 世界モデル（センサ融合・EKF・敵護衛機推定・撃墜推定）
           │
           ├─► 上位方策（オプション選択；ルール司令部 または 学習済みTransformer方策）
           │       ATTACK / ENGAGE / DEFEND / DRAG / FLANK_L / FLANK_R  ×  射撃モード(抑制/通常/積極)
           ├─► 反射層（常時有効）：MWS回避、仮想ミサイル脅威での背面離脱、誘導支援クランク、
           │       場外防止、エネルギー管理（速度依存の上昇角制限）
           └─► 射撃管制：候補射撃ごとに学習済み命中確率 Pk を推定、目標ごとの弾数制御
```

- 上位方策の行動はマクロ行動（5 s ごと）なので、1エピソードの意思決定数は最大360回。
  1 tick ごとに低レベル操舵を学習する公式サンプルに比べ、信用割当の地平が約1/5になり、
  CPU のみでの学習を現実的にしている（セミマルコフ決定過程 / Options framework）。
- 反射層が安全性（回避・場外・失速）を保証するため、学習は「戦術選択」に集中できる。

## 3. センサ融合（レーダとIRSTの使い分け）
- レーダ：真のID付き3次元航跡（射撃に必須）、探知は確率的（10回中6回で航跡確立）。
- IRST：約1.5倍遠くまで見えるが方位のみ、**センサごとの匿名ID**（失探のたびに再採番）。
  → ID照合ではなくデータアソシエーションで統合する必要がある。
- 実装（fusion.py / tracker.py）
  1. 全航跡を EKF（等速度モデル、加速度ノイズ）で予測
  2. レーダ航跡：同一IDの航跡を更新。なければIRST由来航跡を3次元マハラノビス距離でゲートして継承
  3. IRST方位：前回対応付けた匿名IDを優先し、なければ予測方位との正規化角度誤差
     （σ² = σ_IRST² + σ_⊥²/r²）で最近傍対応（3σゲート）
  4. 未対応方位は異なる機体の方位同士で三角測量して新規航跡化
  5. t≈0 に見える方位は護衛対象機（戦闘機は約200 km離れていて見えない）として、周回軌道 x=120 km・
     高度10 km の擬似観測（事前分布）付きで初期化 → 方位1本でも位置が決まる
  6. 撃墜推定：終末誘導中の自弾が目標3 km以内で消失し、同時に目標のレーダ航跡が消えたら撃墜とみなす
- 効果：融合前は匿名IDの重複で敵機数を最大16機と誤認していた → 融合後は実数（≤5）に一致。

## 4. 仮想ミサイルによる見えない脅威の推定
- 敵弾は終末（10 km）まで見えないため、「敵が自機に対する射程内（正規化距離 ≤ k）で正対している」

## 5. 命中確率（Pk）モデル：教師あり学習による射撃判断
### データ
- 実戦ログ：自エージェントの射撃時に、エージェントが観測できる量だけで特徴量を記録
  （射撃管制と同一の関数）し、シミュレータ側の神視点ログ（Hitイベント）で命中/非命中ラベルを付与。
- 交戦ラボ：1対1の射撃シナリオを4組×150エピソード生成（距離8–80 km、アスペクト、高度、
  被射撃機の回避機動7種、射撃後の母機行動3種を無作為化）。実戦では得にくい近距離・正対のデータを補う。
- 実戦とラボでは目標の振る舞いの分布が違う（ベンチマークは予防的に反転する）ため、`is_lab` 指示変数を
  入れて同時学習し、推論時は `is_lab=0`（実戦相当）で予測する（ドメインシフトの補正）。
### 特徴量（16）
正規化射程 rn=(d−R_tail)/(R_head−R_tail)、距離、R_head、R_tail、目標アスペクト、自機の目標オフボアサイト角、
双方高度・速度、接近率、ミサイル推力倍率、目標種別、高度差、敵側R_head(自機への脅威)、is_lab
### モデル比較（グループ化5分割CV：同一試合のサンプルは同じfoldに入れてリーク防止）
| モデル | 主なハイパーパラメータ探索 | log-loss | Brier | AUC |
|---|---|---|---|---|
| 定数（基準） | – | 0.691 | 0.249 | 0.50 |
| ロジスティック回帰 | C ∈ {0.03,…,3} → C=1 | **0.255** | **0.076** | **0.962** |
| LightGBM | 葉数{4,8,16}×木数/学習率×最小葉サンプル | 0.275 | 0.084 | 0.954 |
| MLP | 隠れ層{16,32-16,64-32}×L2 | 0.289 | 0.087 | 0.950 |
- データ量（約700発）ではロジスティック回帰が最良かつ較正良好（予測0.8–1.0の帯で観測0.97）。
  推論は numpy の内積のみ（<0.1 ms）。データが増えた段階で LightGBM（単調性制約付き）に切替可能な実装。
- 係数の解釈：アスペクト（−2.26）と距離（−1.81）が支配的。正対目標は35 km でもPk≈1、背面目標は15 kmで0.5。
### 射撃方針（複合目的）
- 射撃は Pk ≥ しきい値（戦闘機・護衛機で別）でのみ実施し、目標ごとの飛翔中弾数を制限。
- しきい値は「射撃モード」（抑制/通常/積極）で上位方策が切り替え、命中率と撃墜までの時間・生存の
  トレードオフを学習で最適化する。

## 7. 強化学習（上位方策）
### 定式化
- セミMDP：上位方策は5 s ごとに各機のオプション（6種）と射撃モード（3種）を選ぶ。
  低レベル操舵・回避・支援は反射層とスキルが担当（Options framework, Sutton et al. 1999）。
- 中央集権型（M方式）：1つの方策が4機をまとめて扱い、各機の行動は共有パラメータの因子化分布
  π(a|s)=∏_i π(o_i|s)π(m_i|s)。
### 観測とネットワーク
- エンティティ・トークン：全体(10) / 味方4機(33) / 敵航跡8(20) / 護衛機2(8)。
  敵航跡は融合済み（レーダ/IRST/メモリの区別、推定品質、IRST観測数を含む）。
- 2層 Transformer エンコーダ（d=64, 4ヘッド, pre-norm, マスク付き）→ 味方トークンごとに行動ヘッド、
  プーリングで価値ヘッド。約6万パラメータ、CPU推論 ~1 ms。航跡数の増減・機体損耗に自然に対応（置換等変）。
### 報酬設計
- 終端：**競技得点そのもの** r_T = 2×(score−0.5) ∈ [−1,1]（勝利・命中率・時間の複合目的を直接最適化）
- 事象：敵戦闘機撃墜 +0.10、命中 +0.10、外れ弾 −0.06（命中率の圧力）、自機喪失 −0.15
- ポテンシャル型整形 F = γΦ(s')−Φ(s)（Ng et al. 1999：最適方策を変えない）
  Φ(s) = −0.15·d(武装自機, 敵護衛機)/250km + 0.10·d(敵戦闘機, 自護衛機)/250km
### 学習アルゴリズム
1. 模倣学習（BC）：ルール司令部の選択を教師ラベルとして交差エントロピー学習（初期性能をルール並みに）
2. PPO（クリップ0.2、GAE λ=0.95、γ=0.995、価値クリップ、エントロピー0.01）
3. 教師KL正則化：β·CE(教師, π) を β=0.3 から150反復で0へ線形減衰（初期の方策崩壊を防止）
4. リーグ自己対戦：ベンチマーク(固定/ランダム)、ルール司令部、突撃型、籠城型、過去スナップショット。
   PFSP（勝てない相手ほど高頻度：w∝(1−平均得点)^2）で対戦相手を選択し、Glicko-2 評価で重要な
   「多様な相手への頑健性」を確保。
