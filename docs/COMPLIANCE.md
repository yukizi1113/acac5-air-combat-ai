# 暫定ルール（配布 v1.1.0 の不具合対応）への適合確認

## ルール（運営からの通知、要旨）
1. 判断に使ってよいのは、自機・味方機の観測データ（センサ航跡、データリンクの情報を含む）と、時刻・ルールなどの公開情報だけ。相手の機体・ミサイル・エージェントの情報をそれ以外の方法で得ること、シミュレータ内部のオブジェクトの参照・変更は禁止。
2. IRST 航跡の並び順には意味を持たせない。並び順で目標を識別したり、味方機の航跡と照合したりすることは禁止。

## 提出エージェント（agents/TacB, snap_*）が使っている情報

| 用途 | 参照先 | 区分 |
|---|---|---|
| 自機の位置・速度・残弾・性能 | 各 parent の `observables`（motion, weapon, spec） | 自機の観測 |
| 味方護衛機・味方機の状態、味方弾 | `observables['/shared/fighter']` | データリンク |
| 敵機・敵護衛機 | `observables['/sensor/track']`（チーム共有レーダ航跡）、`/sensor/irst/track`、`/sensor/mws/track` | センサ航跡 |
| 戦域の寸法・陣営 | `manager.getRuler()().observables()` の dOut, dLine, eastSider | 公開ルール |
| 時刻 | `manager.getElapsedTime()` など | 公開情報 |
| 見えない脅威の推定 | `createVirtualSimulationManager` で作った仮想シミュレータに、**自分で生成した**仮想誘導弾だけを置き、その状態を読む（配布サンプルの use_virtual_simulator と同じ機能） | 自前の推定 |

- 相手機・相手弾の実体、`manager.getAssets()`、相手エージェントの内部は参照していません（`grep` で確認）。
- **IRST**：方位と、観測に含まれる匿名ラベル（センサごと・失探で再採番）を、同じ方位の時間的な継続の判定だけに使っています。
  - 並び順への依存を除くため、方位リストは処理前に幾何（機体名・方位角）で並べ替えています（agents/TacB/agent.py `_build_world`、2026-10-28 追加）。
  - 並び順で目標を識別したり、味方航跡と照合したりはしていません。
  - 提出済みの zip（v12 まで）はこの並べ替えの前の版で、方位を観測の並び順で貪欲に対応付けていました。並び順で識別はしていませんが、対応付けの結果が並び順に影響されうる点は、次の提出で解消します。

## 解析ツール（提出しない）
`tools/fight_ext.py`（神視点の誘導弾ログ）、`tools/lab.py`・`agents/Lab`（交戦ラボ）、`tools/flight_lab.py`、`tools/esc_lab.py` は、評価と解析のために真値を記録します。これらは対戦を回す側のコードで、提出物には含めていません（`tools/make_submission.py` の FILES 参照）。
